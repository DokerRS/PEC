# Weak Spots, Risks, and Technical Debt

Registry of fragile areas, latent risks, and known repository constraints.

---

## 1. Fragile Modules and High Coupling
- **Modularized Dashboard Frontend & Server View (`src/views/dashboardView.ts` & `src/client/dashboard/`):** Клиентский JS вынесен из монолита в модульный TypeScript (`src/client/dashboard/`) и собирается через esbuild в `public/dashboard.min.js`. Тестовый стенд jsdom (`test/helpers/dashboardDom.ts`) исполняет непосредственно скомпилированный бандл. Сам `dashboardView.ts` генерирует каркас разметки (~158 KB), требуя верификации DOM-тестами (`test/dashboard*.test.ts`).
- **Binary Packaging Engines (`src/appPackager.ts` & `src/packager.ts`):** Highly complex packaging logic (~121 KB and ~52 KB) coupling MinGW-w64 cross-compilers, NSIS/wixl MSI generation, zip archive creation, and Authenticode signing. Heavily dependent on host system toolchains and path resolution.
- **Embedded JavaScript Extension Templates (`src/templates/popupJsTemplate.ts` & `backgroundTemplate.ts`):** Large JavaScript templates (~57 KB and ~74 KB) maintained as TypeScript template literals. Synchronized with `extension/` via `npm run sync:templates`. Syntax errors in template literals bypass `tsc` and fail only at extension runtime.
- **Cross-Layer Theme Contract Duplication Guard (CI-enforced since THEME-2026-11-16):** Theming contracts are duplicated across 5 files in two languages (`src/client/dashboard/core/theme.ts`, `src/appPackager.ts` + `src/routes/appSyncRoutes.ts` (luminance clamps), `client/Windows/gui/pec_imgui_theme.h`, `client/Windows/gui/ui/theme.h`); the palette registry is converged onto the `theme.ts APP_PALETTES` canon (THEME-WEB-4: studio/packager/popup copies synced; `emerald-sentinel`/`minimal-light` — documented aliases of the native header). Since THEME-QA-2 the guard is not a manual discipline: `test/themeHexParity.test.ts` + `test/themePaletteParity.test.ts` assert hex equality canon↔extension-map↔popup↔both native headers (incl. float↔hex comment roundtrip) — a palette edit without synchronized propagation fails `npm test` in CI. Mode-switching heuristics are the shared luminance predicate (THEME-WEB-3), not per-file ad-hoc regex; see architecture.md §2.9.

## 2. Environment and Runtime Constraints
- **Stable Extension ID Invariant (`extension/key.pem`):** Chrome enterprise GPO deployments (`ExtensionInstallForcelist`) depend strictly on the RSA-2048 public key hash. Overwriting or losing `key.pem` permanently breaks extension installation and updates across the entire enterprise AD fleet.
- **Two-Token Model Separation (`ADMIN_TOKEN` vs `EXT_SHARED_TOKEN`):** `EXT_SHARED_TOKEN` is low-privilege and baked into public CRX/GPO artifacts. `ADMIN_TOKEN` grants full management access. If `ADMIN_TOKEN === EXT_SHARED_TOKEN`, `server.ts` aborts with a fatal exit.
- **Container Cross-Compilation Toolchain:** Docker container builds require `mingw-w64`, `msitools`, and `wixl` in the runner image to support on-demand desktop client packaging.
- **File-Based JSON Storage Concurrency (`src/jsonStore.ts`):** Zero external database; persistence relies on atomic temp-file creation and rename. On Windows environments, file locking (`EPERM`/`EBUSY`) requires the explicit unlink-before-rename fallback in `writeJsonAtomic`.
- **SSRF and DNS Rebinding Protection (`src/rotate.ts`):** Outbound requests to 3x-ui panels resolve hostname via DNS (`validateSafeEndpointUrlAsync`) to block rebinding attacks against loopback or RFC1918 private subnets unless explicitly enabled with `ALLOW_INTERNAL_PANEL=true`. Since AUDIT-SEC-2, validated answers are additionally pinned into the fetch itself (`createSsrfPinnedFetch`, frozen `undici` lookup) — see architecture.md §2.4; bypassing the pinned-fetch builder reintroduces the TOCTOU window.
- **PFX Password in Import-Process Env (SEC-3 remnant, known-issue):** The signtool argv/env channel is closed (SEC-3: passwordless `/sha1` flow; P3-B: `PFX_PASS` stripped from the signtool process env), but the PowerShell PFX-import child processes (`src/codeSigner.ts`: `ConvertTo/From-SecureString`, `Import-PfxCertificate`, `X509Certificate2` ctor) still receive the secret via the `PFX_PASS` environment variable (`env: { ...process.env, PFX_PASS: password }`) — required by the `env:`/`$env:` reading pattern, yet readable from any process able to dump that child's environment block. Full closure would need a stdin/read-host or DPAPI-protected secret channel (out of scope for the minimal-diff audit).
- **Stale Committed Binaries with Baked Token (known-issue until DISPATCH-CLOSURE-4):** `templates/app/windows/PEC-App.exe` and `.pristine/PEC-App.exe` embed UTF-16LE `test-admin-token` (@0xA1780) plus the `corp-proxy-secret-token-change-me` fallback (@0xA17B0); committed `PEC-App.msi` embeds the ASCII fallback. Source-side leak is closed (empty `PEC_DEFAULT_FLEET_TOKEN` ×5 in `version_gen.h`), so these artifacts are stale until rebuilt by the release pipeline. Acceptance criterion: bytescan (ASCII + UTF-16LE) finds NEITHER marker across all `templates/app/windows/*` and `.pristine/*`; the locally rebuilt working-copy MSI still carries the corp placeholder and is NOT acceptable.
- **Windows User Profile Caching (`%APPDATA%`):** Desktop client caches profile in `%APPDATA%\ProxyExtensionCorp\pec_profile.pbprofile`. Reinstalling updated packages requires explicit `CompareFileTime` checks against installer defaults to prevent silently serving obsolete configurations.
- **PecProfileLock Lifecycle (THEME-NAT-1):** `g_profileCs` is owned by each GUI main — `InitializeCriticalSection` at the top of `wWinMain`, `DeleteCriticalSection` only after the final `PecSyncStop`; `PecProfileLock` (ui/pec_sync.h) is a real lock in BOTH builds and UI-thread profile RMW (SwitchToProfile, primary-proxy save) must hold it, since the fleet-sync thread RMWs `g_profile` under the same lock. In main.c, code above the `ui/pec_sync.h` include line uses forward declarations — an implicit-int C declaration there breaks the build with C2371.
- **Theme Round-Trip Surface (THEME-NAT-2/3):** light-mode contract spans `theme.ts` (server sanitize) ⇄ `ui/theme.h` ⇄ `pec_imgui_theme.h` with one predicate (lum>175 OR all channels>180) and one dark-card guard (any channel <160 → white); theme adoption is mirrored in both GUI bootstraps (ImGui: full-candidate compare incl. timestamp; GDI: theme/pecSync in-place only). `client/Linux pb_profile` now round-trips `Theme`/`PecSync` blocks verbatim (`theme_json`/`pecsync_json` + jv_dump emitter) — any new Windows-only profile block must be added to that preservation list or it will be silently stripped on Linux save.
- **Unity-Build Update Pipeline Header (`client/Windows/gui/ui/update_core.h`):** Included by both `ui/update.h` (main.c, classic dialog keeps `WM_APP_UPDATE`=WM_APP+6) and `main_imgui.cpp` (defines its own `WM_APP_UPDATE`=WM_APP+8 BEFORE including `update_core.h`; `WM_APP_DLDONE`=+8 belongs to update.h only). Reordering these includes or un-guarding the `WM_APP_*` defines collides message IDs (+8) and breaks the ImGui WndProc switch. Requires `profile/profile.h` (PB_WriteAppLog) in scope before inclusion.
- **vm-Песочницы vs Браузерная Семантика window (test/helpers/dashboardVm.ts, dashboardAppStudio*.test.ts):** В браузере `window === globalThis`, но в node vm-песочницах это разные объекты: studio.ts бриджит `currentLang` через `Object.defineProperty(window, ...)`, а модульный код читает его как bare-идентификатор (резолв в контекст-глобал). Все vm-стенды обязаны объявлять делегирующий аксессор `currentLang` + мок `localStorage` (index.ts читает его на верхнем уровне). Экспозиции идут через `Object.assign(window,{...namespace})` — статический grep `window.FN=` по бандлу НЕ доказывает отсутствие экспозиции (проверять только рантайм-typeof, как в dashboardThemeSyncAndAppStudio).
- **Коммитнутый Бандл как Тестовый Артефакт (public/dashboard.min.js):** 12+ сьютов исполняют коммитнутый артефакт esbuild; рассинхрон `src/client/dashboard` ↔ `dashboard.min.js` маскируется CI drift-гейтом (AUDIT-INFRA-4), но локальные правки клиентского кода без `npm run build:ui` прогоняются против СТАРОГО бандла (тихий false-negative/false-positive). Правило: после правок src/client/dashboard всегда пересобирать бандл до локальных прогонов.
- **Клик-Делегирование vs Прямой Вызов в Тестах (инвариант UX-2, DIAG-GEO-UX-1 — 4-й случай семьи POPOVER-CLOSE):** мёртвая кнопка при живом экспорте функции (`pm-*`-пункты меню пресетов, карточки роутинга) не ловится тестом, вызывающим экспорт напрямую — он минует делегированный document-level слушатель. Инвариант: DOM-стенды обязаны взаимодействовать с контролами только через `dispatchEvent(click/change/keydown)` на реальных элементах (эталон: `test/presetCardMenu.test.ts`, `test/presetBuilderUi.test.ts`), прямые вызовы экспортов — только как доп. ассерты поверх клик-пути, не вместо.
- **waitFor-Флейки DOM-Стенда под Полной Загрузкой Файла ((d)(e) card-menu, GEO-PRESET-UX-2):** переходы DOM после клика (открытие `presetBuilderPage`, импорт-пресет POST) изолированно GREEN, но полным файлом падали на дефолтных 2с — бандл-ревалюция и SharedFixture-загрузка добавляют джиттер. Правило: `waitFor` на DOM-переходы после клика — `timeout: 6000` минимум (эталон: `test/presetCardMenu.test.ts:254,302`) либо вынос сценария в отдельный файл; подтверждено диспетчерской верификацией — флейк тайминговый, не кодовый (изолированный проход GREEN).

## 3. Deferred Technical Debt
- **Process Memory State for Rate Limiting & Instances:** Rate limiters and instance registry rely on in-memory LRU caches (`src/instances.ts`, `src/middleware/security.ts`). Multi-replica horizontal scaling would require external shared caching (e.g., Redis).
- **Automated Template Drift Verification:** Ручная синхронизация (`npm run sync:templates`) закрыта автоматическим барьером в CI (`.github/workflows/ci.yml: template-drift-check`), блокирующим расхождение кода `extension/` и строковых шаблонов `src/templates/`.
- **Linux Credential Storage without Keyring (libsecret deferred, AUDIT-NAT-P3):** Linux-клиент персистит креды файлами 0600 (mkstemp→rename гарантирует права), но без шифрования покоя — интеграция `libsecret` отложена как новая зависимость, требующая infra-согласования (решение в зоне DISPATCH-CLOSURE-4); Windows-путь тем временем закрыт DPAPI (plaintext-fallback удалён в profile.c).

## Release-train rules (REL-1.0.3, 2026-11-25)

- **Pre-tag gate is mandatory and full**: a release train must run `npm run build:ui` + the complete local gate chain (lint, build, full suite, tsc re-run after EVERY edit — TS2561 lesson: a local tsc that predates the last edit proves nothing) BEFORE the tag is pushed. CI-red on the release tree = stop the train (no tag, no publish), fix, re-run.
- **Incident reference**: v1.0.2 was tagged on red CI (Dashboard UI Bundle Drift — src changed without build:ui; REL-OBS-1 changed dashboard sources and the train skipped the rebuild). Published `server.cjs` was verified valid (sha256sums consistent, REL-OBS-1/rotation markers present) — the server artifact was unaffected — but the shipped `dashboard.min.js` in-tree diverged from `src/` until 78cbe6a.
- **Post-tag verification**: after release.yml publishes, download `server.cjs` + `sha256sums.txt`, verify the sums match, and spot-check content markers (feature routes present in the bundle).
